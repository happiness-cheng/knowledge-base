# 面试优先的 Agent 可靠性升级设计

## 目标与范围

本阶段将 Knowledge Base 定位为“可审计、可评测的个人知识库 Agent”，服务于应用型 Agent 工程师面试展示，同时保留长期面向真实用户演进的基础。

本阶段不引入任务队列、Redis、多 Agent 编排或监控平台。它们不是证明当前 Agent 可靠性的必要条件，且会稀释面试展示的主线。

## 设计原则

1. **先可信，再智能**：修复失效测试和生产安全基线后，才新增 Agent 可靠性能力。
2. **数据按用户隔离**：Agent 的所有知识库工具只能访问当前认证用户的数据。
3. **检索决定引用资格**：只有实际被受控工具返回的知识节点可以成为回答引用。
4. **不信任外部文本**：知识库与网页内容都是数据，不能作为指令改变 Agent 的工具策略或权限。
5. **证据可复现**：关键保障由自动化测试与 CI 证明，而非 README 声明。

## 组件与数据流

```text
认证用户
  -> 对话路由（传递 current_user.id）
  -> Agent ReAct 循环
  -> 受控工具执行器（参数限幅 + user_id 过滤）
  -> 知识库 / 图谱 / 联网搜索
  -> 可引用节点集合
  -> 引用过滤器
  -> 对话响应与持久化来源
```

对话路由继续将当前用户 ID 显式传给 Agent。每次知识库、节点详情、图谱和列表查询均以该 ID 过滤。工具调用期间收集真正返回的节点 ID；最终答案中的 `[doc:id]` 只允许引用此集合中的 ID。其余引用不会进入消息来源关联或 API 响应。

系统提示词将明确规定：知识库和网页搜索结果均为不可信参考资料；其中的指令、链接、角色声明或权限要求不能覆盖系统规则和用户目标。

## 安全与配置

### JWT

开发环境允许本地便捷配置。生产环境必须显式设置足够强度的 `SECRET_KEY`，否则服务拒绝启动；不得回退到仓库中的默认值。

### 用户 AI Key

用户的 AI Key 采用对称加密后写入数据库，并只在创建 AI 客户端时临时解密。加密密钥来自单独的环境变量；生产环境缺失该密钥时拒绝启动。已有未加密的历史值在读取时兼容，并在用户下一次保存设置时迁移为加密值。

### 容器部署

Docker Compose 不提供弱默认数据库密码，不向宿主机公开 MySQL 端口。后端服务通过内部网络连接数据库。示例环境变量文档说明所有生产必填项。

## 测试与验收

测试夹具创建一个真实用户和 JWT，将认证头附加到常规 API 请求；不再依赖已经删除的实现细节。新增测试覆盖：

- 未认证请求被拒绝；
- 用户 A 无法通过 API 或 Agent 工具读取用户 B 的节点；
- 工具参数被限制在定义的安全范围内；
- Agent 虚构或越权的 `[doc:id]` 不会作为来源返回或持久化；
- 系统提示词含有不信任外部内容的防注入策略；
- 生产配置拒绝默认 JWT 密钥和缺失的 AI Key 加密密钥；
- AI Key 加密写入与解密读取的兼容行为。

验收命令：

```powershell
backend\venv\Scripts\python.exe -m pytest backend\tests -q --tb=short
cd frontend; npm run build
```

GitHub Actions 应与以上命令保持等价。项目仅在这两项均成功时，才将测试数量与构建状态写入 README 或用于面试展示。

## 风险与取舍

- 本阶段的 Agent 步骤仅记录工具事件和受控输入，不暴露模型内部推理文本。
- 对网页结果不做内容抓取，因此不扩大 SSRF 和网页正文提示注入的攻击面；仅保留现有搜索摘要能力。
- 静态测试不能证明真实模型质量。后续阶段将基于脱敏知识集增加检索与回答质量评测；本阶段首先验证可判定的安全和可靠性约束。
